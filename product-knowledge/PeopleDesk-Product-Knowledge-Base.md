### WF-03 Employee lifecycle — Verified (Medium)

Hiring decision → onboarding record (optionally from external recruitment system) → candidate self-fills via public link → HR promotes to employee (`empEmployeeBasicInfo`; joining date starts gratuity and earn-leave clocks) → placement and salary assignment → probation → confirmation (`dteConfirmationDate`; accrual eligibility) → active service with movements (increment, promotion, transfer; each approval-routed and effective-dated) → separation → clearance → final settlement (WF-02) → ex-employee record retained. Evidence: `PROC-employee-lifecycle.md`; `DT-employee-lifecycle.md`; handbook §6.1.

### WF-04 Compensation change — Verified (Medium)

Increment / promotion / transfer with effective date → new `pyrEmployeeSalaryElementAssignHeader` (prior set `isActive = 0` and kept as history) → if effective date is earlier than the current month, an arrear run (`sprPyrArearSalaryGenereateProcess`, scheduler every 2 min) → next payroll uses the new base, which ripples into OT, gratuity and PF. Evidence: `PROC-compensation-change.md`; `DT-arrear-salary.md`; `DT-salary-assignment-increment.md`.

### WF-05 Attendance process — Verified

Employee punches (biometric device push or scheduled collector, mobile with geo-fence, web) → raw rows in `timePunchMechineRawData` → `AttendanceRequestProcess` job (2 s poll) runs `saas.sprMasterAttendanceProcess` → matched to rostered shift (night shifts attributed to the shift's business date) → daily status (present, late, half-day, absent, leave, holiday, weekly-off) in `timeAttendanceDailySummary` → exceptions raise adjustment / overtime requests through WF-07 → confirmed attendance feeds leave and payroll. Rosters are generated monthly by scheduler. Evidence: `DT-attendance-processing.md`; `DT-roster-shift-generation.md`; `API-scheduler-jobs.md`; handbook §6.2.

### WF-06 Leave management — Verified

Employee checks balance → applies → validated against policy and balance (excess becomes unpaid leave; overlapping requests rejected) → routed through WF-07 (application type 8) → approved: balance deducted, attendance days marked as leave, unpaid portion passed to payroll; rejected: balance untouched. Balances are maintained by scheduled accrual jobs (two engines coexist: `timesheet.sprEmployeeLeaveBalanceGenerate*` and legacy `saas.sprAllLeaveBalance*`, NHV-ATT-04). Cancellation restores the balance. Evidence: `DT-leave-balance-generation.md`; `DT-earn-leave-accrual.md`; handbook §6.3.

### WF-07 Approval process — Verified

Request submitted → `SendToApprovalPipeline` snapshots the application into `ApprovalApplicationHistory` and stamps one `ApprovalTransaction` per configured stage (`ApprovalConfigHeader` / `ApprovalConfigRow` per application type × account / BU / workplace group / workplace; `isInSequence`, `intRandomApproverCount`) → stage approver notified → approve advances to next stage, reject closes the pipeline → route complete: `isPipelineClosed = 1 AND isReject = 0` makes the transaction effective (EP-05) → applicant notified. **If no pipeline is configured for the type and scope, the request is auto-approved.** Admin actions outside the route are recorded via `IsActionByAdmin`. Housekeeping: `ClearApprovalTransaction`, `CloseEmployeePendingApplications` on separation. Evidence: `DT-approval-workflow.md`; `CAP-approval.md`; handbook §6.5.

### WF-08 Loan lifecycle — Verified

Application (amount, instalments, interest, guarantor) → eligibility (PF loan: contributions plus share of returns less outstanding PF-loan principal; one active PF loan at a time) → WF-07 (application type 31 for PF loan) → approved amount and schedule recorded → instalment deducted in every payroll run (WF-01 step 7) → closure, early settlement (must be less than total outstanding), or recovery from final settlement (WF-02). Evidence: `DT-loan-lifecycle.md`; `DT-loan-advance-salary-deduction.md`; `CAP-loan.md`; handbook §6.6.

**Gap (Verified):** the Knowledge Base has no dedicated L1 process documents for leave, attendance, recruitment or approval; those flows are reconstructed here from L3 decision tables, L4 capability documents and the official handbook. The `variants/` folders referenced by the process layer do not exist on disk.

## 19. Limitations and risks

Risk ids are stable for traceability. Severity follows the source assessments; every item is **Verified** against source or extraction unless marked.

### 19.1 Security (see §15)

| ID | Risk |
|---|---|
| RISK-01 | Server-side authorization does not exist; any authenticated user can invoke any in-tenant endpoint (NHV-SEC-01). |
| RISK-02 | Passwords are Base64-encoded, not hashed; credential compromise is total on any database read. |
| RISK-03 | HR documents downloadable without authentication across tenants by id enumeration, and unlogged. |
| RISK-04 | Production secrets committed to git in four repositories; JWT signing key shared across services. |
| RISK-05 | JWTs parsed without signature validation for tenant identity and in Google SSO handlers; Development environment disables authorization. |
| RISK-06 | GraphQL unauthenticated; JWT audience validation disabled; DB transport unencrypted; token in `localStorage`; CSP commented out. CORS any-origin and unwired rate limiting were found by the VAPT plan and appear remediated or in progress in current source (§15). |

### 19.2 Money-path correctness

| ID | Risk |
|---|---|
| RISK-07 | Live payroll procedure differs from git (127 lines; a tenant branch in no repository) — money-path logic is not fully under source control (NHV-DATA-02). |
| RISK-08 | Suspected defects: payslip Tax/PF lines emit the loan amount (NHV-RET-05); PF double-count in settlement (NHV-RET-04); Ad-Din gratuity double-pay (NHV-RET-01); late-punishment literal mismatch zeroes deductions (NHV-PAY-11); late deduction outside the net bracket (NHV-PAY-04); bonus function may ignore configured percentage (NHV-PAY-06); LWP config leave-type mismatch (NHV-PAY-10); self-referential advance-salary join (NHV-PAY-05). |
| RISK-09 | Payroll processing is not transactional: nine independent `SaveChangesAsync` on the payroll path, zero `BeginTransaction`, against a schema with no constraints. |
| RISK-10 | 15 monetary columns stored as `float`, five holding live PF balances. |
| RISK-11 | Two leave-balance engines and four gratuity engines coexist; canonical choice per account unknown (NHV-ATT-04, NHV-03). |
| RISK-12 | No statutory tax-slab engine; monthly tax is a keyed amount; slab changes are code changes (NHV-PAY-02). |
| RISK-13 | Final settlement persistence path unresolved (NHV-RET-02); PF-loan eligibility not enforced server-side. |

### 19.3 Architecture and data

| ID | Risk |
|---|---|
| RISK-14 | 34% of stored procedures branch on hardcoded tenant ids; onboarding a customer with a payroll or device variation is an engineering change and redeploy; no tenant-behaviour register (NHV-TEN-03). |
| RISK-15 | Integrity is 100% code-enforced (3 no-op FKs, 0 check constraints); deletions can silently orphan rows. |
| RISK-16 | Approval engine mutates 33 `DbSet`s across modules; no module owns its own data. |
| RISK-17 | Two architectures ship at once (legacy controllers vs minimal APIs; 12% CQRS); 1,509 untyped responses; 0 declared contracts; no versioning on the main API; DB Hungarian names leak into the API. |
| RISK-18 | Largest service class ~22,800 lines; 42 blocking `.Result` calls on payroll and leave paths; 5,248 `: any` annotations in the frontend. |
| RISK-19 | Approval auto-approves when no pipeline is configured — a configuration omission becomes an authorization bypass on money-routed transactions. |
| RISK-20 | Destructive procedures present in the database (`DeleteNonAccountData`, `DeleteDataExceptAccount5`, `core.sprAccountPermanentlyDelete`); 23 dead-suspect SQL objects and two unrunnable salary generators. |
| RISK-21 | Cross-tenant leak paths in permission query, pending-application closure and legacy gratuity lookup (NHV-SEC-08, NHV-MISC-07, NHV-RET-06). |
| RISK-21a | GL posting to Managerium is a cross-server write to a linked server addressed by hardcoded IP (NHV-MISC-05); encrypted salary columns coexist with plaintext and the authoritative source is unknown. |

### 19.4 Operations and delivery

| ID | Risk |
|---|---|
| RISK-22 | Single-instance constraint on all four services (no backplane, in-process cache and rate limiter, non-clustered in-memory Quartz, startup DDL); deploy = downtime; scheduler is a SPOF for payroll. |
| RISK-23 | Quartz misfires lost across restarts; `BackgroundServiceExceptionBehavior.Ignore` silently kills jobs; failures are unpolled rows. |
| RISK-24 | No functioning CI quality gate: 0 tests in CI, lint broken, no scans; real pipeline definitions outside version control. |
| RISK-25 | No observability: no structured logs, APM, tracing, metrics, health probes or alerting (all selected and switched off). |
| RISK-26 | No backup/restore, RPO/RTO or DR artifact in any repository. |
| RISK-27 | .NET 9 runtime out of Microsoft support since 12 May 2026 across 40 projects; `iBosSignalR` on .NET 6 (out of support since Nov 2024). |
| RISK-28 | `BackgroundJobSuccessHistory` grows ~240K rows/day with no retention (NHV-AUD-01). |
| RISK-29 | Wildcard TLS certificate expires 26 Oct 2026; single nameserver; private IPs in public DNS; no SPF/DMARC. |
